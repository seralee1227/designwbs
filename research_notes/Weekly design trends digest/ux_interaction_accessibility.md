## What new interaction patterns are gaining traction (generative UI, conversational interfaces, micro-interactions, scroll storytelling, spatial/3D)?

### Takeaway
The dominant 2026 narrative is a shift from static, author-designed screens toward AI-assembled, goal/intent-driven interfaces ("generative UI") and multimodal/agentic interaction, with Nielsen Norman Group (NN/g) framing trust as the defining design challenge this creates; meanwhile scroll-driven storytelling has matured into a native-CSS, performance-safer pattern, and spatial/3D web UI is described as moving from demo to limited production use via WebGPU reaching Baseline status. No single item is confirmed as breaking news from the last 2-4 weeks; these are ongoing 2026 trajectories.

### Cited Findings
- NN/g defines "generative UI" (GenUI) as "a user interface that is dynamically generated in real time by artificial intelligence to provide an experience customized to fit the user's needs and context," co-written by Kate Moran and Sarah Gibbons — cited via [axup Substack](https://axup.substack.com/p/ai-ux-generative-intent-based-product) and discussed on NN/g VP Kate Moran's appearance on the [Knapsack Design Systems podcast](https://www.knapsack.cloud/blog/kate-moran-humans-are-essential) (direct nngroup.com article not independently fetched — unverified beyond secondary citation).
- A consultancy citing NN/g's "State of UX 2026" states that "trust is now the defining design challenge" for dynamic/generative interfaces — [Foolproof](https://foolproof.co.uk/journal/what-is-gen-ui-and-does-it-matter) (secondary citation of NN/g; original State of UX 2026 report not directly fetched).
- Designer Roger Wong has pushed back publicly on generative-UI enthusiasm, arguing AI-generated actions can get in the way of users rather than help — cited via [Foolproof](https://foolproof.co.uk/journal/what-is-gen-ui-and-does-it-matter).
- Multiple 2026 trend roundups (vendor/agency blogs, not news) converge on: multimodal/agentic input replacing single-mode tap-click-type interaction; "goal-based"/intent-driven UX replacing step-by-step commands; and accessibility/dark mode described as "baseline" expectations rather than differentiators — [UX Design Institute](https://www.uxdesigninstitute.com/blog/the-top-ux-design-trends-in-2026/), [dev.to roundup](https://dev.to/margalit_rice_47962d9a22c/five-interface-shifts-already-pointing-to-how-digital-products-will-feel-in-2026-2b57).
- CSS `scroll-timeline` and `view-timeline` properties have moved from experimental to "broadly shipped" browser support, enabling JavaScript-free scroll-driven animation; a cited claim states JS-driven scroll handlers were "the single most common reason scroll storytelling tanked Interaction to Next Paint scores" — source is a guide found via search, not an original named outlet (treat as a secondary/aggregator claim, not independently verified against caniuse or a named author).
- A W3C workshop note on the "WebSpatial" topic argues interaction models for 3D/spatial web need to move past simple pointer events toward spatial gestures and dedicated APIs — [W3C WebSpatial minutes, Nov 2025](https://www.w3.org/2025/11/10-webspatial-minutes.html).
- WebGPU is reported to have reached Baseline browser-support status as of around January 2026, per [VR.org](https://vr.org/articles/webgpu-baseline-2026-three-js-webxr-default); a separate source (WPRiders) claims WebGPU now runs in Chrome, Edge, Firefox, and Safari across desktop and mobile, while another guide says Safari support is still "partial" and recommends a WebGL fallback — **sources conflict on Safari's WebGPU maturity**; treat browser-support specifics as unverified without a direct caniuse.com check.
- Commercial spatial-web use cases cited: product configurators, virtual showrooms, and "scrollytelling about us" pages; Gaussian Splatting flagged as an emerging capture technique for real-estate/museum virtual tours — [search synthesis, multiple agency blogs], with explicit caution that "35% longer retention" (attributed to unnamed "Google Design research") and "65% of new web apps" (attributed to the 2025 Web Almanac) figures circulating in sector blogs could not be verified or linked to primary sources.
- Guidance from spatial-UX writers: 3D/spatial elements should not be forced on users — critical content should remain reachable without spatial interaction, and auto-playing 3D on page load is explicitly listed as a design mistake to avoid.
- On conversational UI replacing forms: sources (mostly vendor blogs, several dated 2016–2018, so largely legacy context rather than new) distinguish "conversational forms" (fixed branching question paths) from true chatbots (open-ended NLP), and suggest chatbots suit nuanced/high-ambiguity tasks while short-form UI remains faster for simple conversions (e.g., newsletter signup) — [onething.design](https://www.onething.design/post/best-practices-for-conversational-ui-design), [orbitforms.ai](https://orbitforms.ai/blog/what-is-conversational-ui-design). No 2026-dated primary research was found specifically validating conversion-rate claims (e.g., Amtrak, Knorr figures cited elsewhere are vendor-sourced and unverified).
- Micro-interaction discourse in 2026 emphasizes subtlety over spectacle: a shift away from heavy animation libraries toward small effects (hover states, button feedback), increasingly paired with haptic feedback on supporting mobile hardware — [dev.to](https://dev.to/alldivitools/5-small-ux-trends-that-make-websites-feel-modern-in-2025-2026-5100), [UXmatters, Oct 2025](https://www.uxmatters.com/mt/archives/2025/10/evoking-emotion-and-enhancing-engagement-with-microinteractions.php).

### Inferences
- The industry conversation has largely moved from "should AI generate UI" to "how do we keep generated/dynamic interfaces trustworthy and usable" — the repeated emphasis on trust (NN/g) and pushback (Wong) suggests generative UI is past the hype-only phase and into a more critical, applied discourse.
- Scroll storytelling's move to native CSS primitives suggests performance concerns (Core Web Vitals / INP) are now a first-class constraint on this pattern, not an afterthought — design teams adopting scrollytelling in 2026 are likely expected to justify it against INP budgets.
- Spatial/3D web claims remain aspirational/marketing-heavy; actual production adoption outside of niche commerce use cases (configurators, virtual showrooms) appears limited, and cross-browser parity (especially Safari) is still a live constraint for teams considering WebGPU-first builds.

## What's new in accessibility standards or practice (WCAG, browser/OS features, inclusive design, regulatory developments)?

### Takeaway
There is no WCAG 2.3 in active development; W3C's near-term focus is WCAG 2.2 maintenance/errata (ongoing through 2026) plus continued WCAG 3.0 draft work (an updated public working draft reported in March 2026, with a further update reported around September 2026), alongside the related EN 301 549 v4.1.1 standard being officially published September 2, 2026. EU Accessibility Act enforcement entered a more active "Year 2" in mid-2026, but enforcement intensity still varies sharply by member state, and in the US, the regulatory and legislative picture is unusually unsettled — a 2025 DOJ guidance-document withdrawal, an April 2026 delay of the Title II web-accessibility compliance deadline, and dueling pro- and anti-plaintiff bills in Congress.

### Cited Findings

## What's the current discourse on AI-generated UI/design and its impact on interaction design and accessibility?

### Takeaway
The discourse has shifted from early (2023) alarm about AI tools like v0 producing inaccessible interfaces toward a more nuanced 2025-2026 consensus: tools built on accessible component foundations (e.g., v0 on shadcn/ui on Radix) inherit better accessibility defaults than raw LLM code generation, but automated/AI-generated output still requires mandatory manual accessibility review, and cited (if unverified) research suggests a majority of raw AI-generated interfaces still fail basic accessibility checks without explicit accessibility guidance baked into the generation process.

### Cited Findings
- Early critique (2023): designer Sophie Koonin publicly raised accessibility concerns about Vercel's v0 UI-generation tool shortly after its alpha release — ["AI, and the trouble with inaccessible SaaS"](https://localghost.dev/blog/ai-and-the-trouble-with-inaccessible-saas/). Designer Heather Buchel separately argued output isn't production-grade if the generated code is inaccessible — [heather-buchel.com](https://heather-buchel.com/blog/2023/09/ai-generated-ui-is-not-innovative/).
- A practitioner account (dated to around March 2025) describes a v0-generated modal that could not be closed with the Escape key and lacked a focus trap — cited as an anecdotal/single-case finding, not a systematic audit — [Enterprise DNA practitioner roundup](https://enterprisedna.co/resources/blog/practitioner-v0-frontend-real).
- v0 is built on shadcn/ui, itself built on Radix UI's accessibility primitives; a Frontend Masters analysis argues v0's output inherits Radix's accessibility contracts by default, though it still recommends auditing all v0-generated components for accessibility rather than assuming compliance — [Frontend Masters, "AI-Generated UI Is Inaccessible by Default"](https://frontendmasters.com/blog/ai-generated-ui-is-inaccessible-by-default/).
- A cited (secondhand, unverified-against-original-study) 2024 finding states 84% of ChatGPT-generated websites exhibited accessibility violations around text resizing, contrast, and semantic relationships — referenced within a 2025 academic paper on LLM-generated code and UI accessibility barriers — [a11y-paradise review](https://a11y-paradise.onrender.com/reviews/69ae41f68b9c91225e628c18); a separate usability study (not v0-specific) is cited as finding users succeeded only 63% of the time on raw AI-generated screens — **both figures are secondhand citations, original studies not independently verified**.
- A design-homogeneity critique (not strictly an accessibility point) notes that Tailwind creator Adam Wathan's joke about the framework's default indigo button color is cited as contributing to widespread AI-generated UIs defaulting to indigo/similar palettes — a commentary on design sameness driven by AI tools' reliance on common component libraries — [search synthesis].
- NN/g's generative-UI framing (see Interaction Patterns section above) implies accessibility stakes are rising with GenUI specifically because interfaces assembled dynamically at runtime cannot rely on a designer having manually verified each possible generated state — [axup Substack](https://axup.substack.com/p/ai-ux-generative-intent-based-product) (inference drawn from NN/g's framing, not a direct NN/g accessibility statement — flagged as an inference, see below).

### Inferences
- The maturing discourse suggests the real accessibility risk from AI-generated UI is concentrated in two places: (1) tools/teams that generate raw UI code without an accessible component foundation (higher risk), and (2) generative UI systems that assemble interfaces dynamically at runtime, where no human reviewer sees every possible generated state before it reaches a user — this second category (true runtime GenUI, as opposed to one-time AI-assisted scaffolding like v0) appears to be the less-examined, higher-risk frontier not yet covered in depth by the sources found.
- Design tool vendors (Figma, Stark, Deque — see above) are responding to this exact gap by building automated AI accessibility scanning directly into the design/testing pipeline, which can be read as an implicit industry acknowledgment that AI-generated-or-assisted design needs AI-powered accessibility QA to keep pace.

### Gaps
- No rigorous, recent (2026), independently-verifiable study quantifying accessibility pass/fail rates for AI-generated UI across major tools (v0, Figma AI, Framer AI, etc.) was found — the most-cited statistics (84%, 63%, 49.3%/97.3%) are all either secondhand or self-reported by a vendor (Intopia) with its own stated caveat about independent validation.
- No discourse specifically addressing accessibility risk in *true runtime* generative UI (interfaces assembled live per-user, as opposed to AI-assisted one-time code scaffolding) was found — this is flagged as a notable blind spot in current design press coverage, worth flagging to the report writer as an open question rather than a researched finding.
